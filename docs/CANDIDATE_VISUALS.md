# 후보 사진·아트 설계 제안

2026-09-20. **설계만 작성. 사진 수집·API 가입·키 발급·이미지 생성·새 저장소·DTO 변경은 미실행**이다. 이번 구현은 대결 연출/라운드 구분이며 사진은 별도 후속 범위다.

## 추천: 검토한 사진 재사용 + 통일된 SVG 아트

사진은 활동을 한눈에 이해하기 좋지만, 관련 없는 예쁜 사진은 선택을 왜곡한다. 매 요청 검색/생성 대신 공용 후보 카탈로그에 사진을 사전 연결하는 방식을 추천한다. 일반 자연어의 신규 후보까지 사진으로 억지로 채우지 않는다.

| 방식 | 준비/비용/속도 | 판단 |
| --- | --- | --- |
| 검토한 스톡 사진·직접 촬영 재사용 | 매칭·권리 확인 필요. 요청당 생성비0, 전송/저장 비용과 로딩은 존재 | 기본 후보부터 추천 |
| 매번 외부 사진 검색 | API키·요청 제한·출처 처리·지연·오매칭 | 실시간 생성 경로에서 제외 |
| AI 이미지 생성 | 별도 생성비/대기/검수 필요 | 초기 미적용. 추후에도 오프라인 공용 자산으로 생성 후 재사용 |
| 통일된 SVG 아이콘/기하학 아트 | 개념 매핑 필요. 요청당 외부 호출0 | 사진 없는 후보의 기본 대체안 |
| 시스템 이모지 | 빠르고 외부 호출0, 플랫폼별 모양 차이·추상 개념 한계 | 보조안 |

이미지 생성 모델/가격은 정하지 않았다. 생성 호출비0을 서비스 전체 운영비0으로 표현하지 않는다.

## 1차 적용 제안

1. 자주 쓰는 취미16종부터 검토한 사진을 연결하고 기존64개 카탈로그로 확장한다. 아직 확보한 사진은 없다.
2. 새롭거나 추상적인 후보에는 책/실/커피/코드처럼 구별되는 로컬 SVG 아트. 개념이 불확실하면 중립 도형을 쓴다.
3. 양쪽 사진의 높이·명도·크롭·텍스트 크기를 맞춰 한쪽 사진의 화려함이 선택을 압도하지 않게 한다. 현재 흑백 CSS도 음식·미술의 구별에 색상이 필요한지 별도 검토한다.
4. 이미지 실패는 생성 실패가 아니다. 기존2초 fallback 뒤에는 늦게 사진을 갈아끼우지 않고 양쪽 준비 완료 후7초를 시작한다.

## 소스와 사용 조건

- 초기 소량 수동 큐레이션은 Pexels 또는 직접 촬영을 우선 검토한다. 일반 라이선스는 무료 사용/수정·웹/앱 사용을 허용하지만, 인물의 부정적 사용·상품 보증 암시·스톡 재배포 등을 제한한다. 출처/작가/확인일을 남기고 인물·로고·브랜드 중심 사진을 피한다. [Pexels 라이선스](https://www.pexels.com/license/)
- API 조건은 일반 다운로드 라이선스와 별도다. Pexels API는 계정/키와 크레딧 지침을 제공하므로 실제 도입 때 최신 조건·한도를 다시 확인한다. 지금 추천은 키 없는 수동 검토다. [Pexels API](https://www.pexels.com/api/documentation/)
- Unsplash API는 반환 URL 직접 사용(hotlink)과 API 크레딧 지침 준수를 요구한다. 임의 자체 CDN 복사와 혼용하지 않는다. 초기 demo50요청/시간이므로16장씩 즉석 검색하는 구조도 피한다. [Unsplash API](https://unsplash.com/documentation)
- 아트는 직접 작성한 SVG 또는 라이선스를 보존한 아이콘 파일이다. Lucide는 ISC 및 일부 Feather 유래 아이콘 고지 조건을 확인하고 함께 배포해야 한다. OS 이모지 그림을 추출해 재배포하지 않는다. [Lucide 라이선스](https://lucide.dev/license)

## 연결 경계 — 아직 미구현

현재 Candidate의 nullable `imageUrl`에는 출처/라이선스/아트 의미 필드가 없다. URL만 곧바로 붙이는 것으로 설계가 끝나는 것은 아니다.

- 백엔드: 검토된 media manifest에 `assetId`, 정확한 개념/alias, 종류, 버전 URL, 원본 페이지, 작가, 사용 조건/확인일, 크롭 위치, 활성/회수 상태를 둔다. 요청마다 바뀌는 `c1` 같은 ID로 공용 자산을 매핑하지 않는다.
- 후보 선택 후 확실한 등록 개념에만 서버가 자산을 연결한다. 조건 때문에 의미가 달라진 후보는 억지 사진 대신 아트. 원문 고민을 외부 이미지 업체로 자동 전송하거나 추가 LLM 호출하지 않는다.
- 프론트: CandidateArt가 photo→정해진 icon/art→중립 카드 순으로 표시한다. 미리보기·대결·Champion·공유에서 같은 자산을 사용하고 이름을 주 정보로 유지한다.
- 공동 계약: 출처/아트 키를 전달하는 선택적 visual 메타데이터를 OpenAPI·Java·생성 TS·fixture에 함께 추가하는 후속안을 검토한다. 기존 `imageUrl=null` snapshot 호환을 보존한다. 정확한 DTO는 구현 전에 확정하며 이번에 몰래 변경하지 않는다.
- freeze 시 자산 버전과 표시 메타데이터도 고정한다. 같은 URL을 다른 사진으로 덮어쓰거나 공유 때 새 검색 결과를 넣지 않는다. 권리 회수/외부404는 중립 fallback으로 처리하고 후보·대진·규칙은 그대로 둔다.
- 자체 호스팅이 허용된 작은 자산은 기존 웹 배포에 버전 고정 파일로 포함하는 방식을 우선한다. 새 유료 CDN은 필요 없다. 임의 URL 서버 다운로드는 SSRF/용량/콘텐츠 검사가 필요한 별도 기능이므로 넣지 않는다.

## 후속 완료 조건

대표 카드 몇 개로 먼저 사용자와 스타일을 맞춘 뒤 구현한다. 의미 일치·출처·360px 크롭·긴 이름·키보드·느린 이미지/404·2초 fallback·7초 보존·동일 공유를 검증한다. 사진 없는 후보를 품질 FAIL로 취급하지 않는다.
