# FE-001 — 입력·강수·전체 미리보기

담당 A — 플레이 경험. 상태: **착수 가능 / 아직 구현 완료 아님**. [시작 안내](../FRONTEND_HANDOFF.md)의 서버 브랜치와 실행 순서를 먼저 확인합니다.

## 결과와 작업 경계

사용자가 고민과 8/16/32강을 선택하면 생성 상태를 보여주고, 검증 완료된 후보 N개 전체를 미리 봅니다. 전체 재생성은 성공 교체 기준 한 번, 시작하면 서버의 frozen snapshot과 sessionId를 다음 게임 단계에 넘깁니다.

- 소유: `frontend/**`의 화면·스타일·API client·mock/상태 로직·관련 테스트. 자동생성 `src/api/schema.d.ts`는 직접 편집하지 않습니다.
- 기준: [Design Spec](../../DESIGN_SPEC.md), [API 계약](../API_CONTRACT.md), [OpenAPI](../../contracts/openapi.json).
- 제외: 실제 AI/검색, 서버 DB, FE-002의 타이머/대진 실행, FE-003 공유 화면, 최종 디자인 승인. 서버 취소·추가 질문 API를 임의로 새로 만들지 않습니다.
- 시작 버튼의 완료 경계: 정상 start 응답을 받아 `sessionId + snapshot`을 FE-002 연결 지점에 전달. 아직 없는 게임을 가짜 완료 화면으로 표시하지 않습니다.

## 구현 순서

1. 기존 fixture import와 생성 타입을 읽고 API 호출/화면 상태를 분리합니다. fixture와 HTTP 구현은 같은 client interface로 바꿔 끼울 수 있게 합니다. fixture는 개발용 표시를 유지합니다.
2. 고민 입력·강수 선택·유효성 검사와 생성 버튼을 만듭니다. 기본 강수는 16, 선택 횟수 7/15/31 안내, 로그인 요구 없음.
3. 생성 접수와 job polling, READY/FAILED 분기를 연결합니다. polling effect 중복과 화면 이탈 시 정리를 테스트합니다.
4. 후보 전체 preview와 전체 재생성, expectedVersion과 idempotency 처리를 연결합니다.
5. start 응답을 게임 연결 지점에 전달하고 아래 체크리스트를 확인합니다.

화면 분할·컴포넌트 구성·시각 디자인은 기존 코드에 맞춰 A가 제안합니다. 새 상태관리/라우팅 의존성은 먼저 현재 방법으로 가능한지 확인합니다.

## 상태별 화면과 동작

| 상태 | 보여줄 것 | 허용 / 금지 |
| --- | --- | --- |
| 입력 | 고민, 강수 8/16/32, 생성 버튼 | 공백 고민·500자 초과는 안내, 유효한 입력만 제출 |
| 생성 접수 중 | 제출 중 안내 | 같은 동작의 중복 제출 금지; key/body 보관 |
| QUEUED/RUNNING | 생성 대기 표시 | jobId로 polling. 후보 이름 미리 노출 금지 |
| 생성 FAILED | 실패 안내·입력 수정·새 시도 | 무한 자동 재생성 금지. 사용자 새 시도만 새 key |
| READY preview | N개 카드, 잔여 재생성, 시작 버튼 | 이름·이미지/fallback·태그 최대 2개. 개별 후보 편집 없음 |
| 재생성 중 | 이전 preview + 교체 대기 표시 | 이전 후보를 지우지 않기. 시작·추가 재생성 잠금 |
| 재생성 실패 | 이전 preview + 실패 안내 | 기존 version/잔여 회수 유지. 결과 재조회/입력 수정 가능 |
| 재생성 성공 | 새 N개 전체 preview | 서버 version/잔여 값으로 교체, 잔여 0이면 재생성 금지 |
| 시작 중 / 결과 불명확 | 시작 처리 표시 | 동일 key/body 재전송 가능, 다른 후보 수정 금지 |
| 시작 성공 | 게임 연결 지점 | snapshot/session 보관. draft GET으로 되돌아가서 후보 변경하지 않기 |

재생성 요청 응답이 유실됐으면 곧바로 이전 READY를 확정하지 말고 같은 key/body로 접수 결과부터 복구합니다. 화면에 이전 preview가 남아 있다는 사실과 서버의 READY 여부는 다릅니다.

## 오류와 재시도

| code / 상황 | FE-001 처리 |
| --- | --- |
| INVALID_INPUT | 입력 또는 개발 중 요청 형식을 확인. 사용자 입력을 보존하고 수정 안내 |
| QUALITY_GATE_FAILED / UNSUPPORTED_REQUEST | 후보를 표시하지 않고 조건 수정·새 시도 안내 |
| CLARIFICATION_REQUIRED | 현재 계약에는 구체 질문 필드가 없음. 고민을 더 구체적으로 수정하도록 안내; 다단계 질문 UI를 임의 구현하지 않기 |
| PROVIDER_UNAVAILABLE | 일시 장애 안내. dev profile/서버 연결 확인. terminal job 실패 후 사용자 새 시도는 새 key |
| RATE_LIMITED | 즉시 자동 재시도하지 않고 Retry-After 이후 시도 안내 |
| OPERATION_IN_PROGRESS | 이미 추적 중인 job을 계속 확인. 다른 탭의 작업이면 이전 preview를 보존하고 잠금/대기 상태로 재조회 |
| VERSION_CONFLICT | 최신 preview를 다시 읽고 후보 변경 사실을 보여주기. 사용자가 보지 않은 새 후보로 자동 시작하지 않기 |
| REGENERATION_EXHAUSTED | 최신 상태를 다시 읽고 재생성 버튼 비활성화 |
| ALREADY_FROZEN | 이미 보관한 start 결과로 이어가기. 없으면 보관한 start version/key로 응답 복구; 현재 계약에 없는 세션 목록 API를 추측하지 않기 |
| NOT_FOUND | 익명 cookie 유실·리소스 만료 가능성을 포함한 이용 불가 안내. 없는 후보를 fixture로 대체하지 않기 |
| IDEMPOTENCY_CONFLICT | client의 key/body 관리 오류. 새 key로 조용히 자동 제출하지 말고 오류 기록/안내 |
| 네트워크 실패 / HTTP 5xx | 입력·key·body·jobId를 보존. 결과 불명확 POST는 같은 key로만 재전송, GET은 제한된 재조회. 실패했다고 즉시 새 generation 만들지 않기 |

서버의 영어 message는 진단 정보이며 화면 문구를 그대로 고정하지 않습니다. code별 사용자 안내를 준비하고 원문 고민이나 cookie를 로그에 남기지 않습니다.
